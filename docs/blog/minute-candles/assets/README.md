## 설명용 삽화 원칙

- 흰 종이 위에 검정·네이비 펜으로 직접 정리한 기술 노트처럼 표현합니다.
- 파랑과 초록만 제한적으로 사용하고 네온, 그라데이션, 3D, 유리 카드와 광고 느낌을 피합니다.
- 이미지 안의 글자를 최소화하고 정확한 뜻과 한계는 대체 문구와 캡션에서 설명합니다.
- 손그림에는 실제 수치, 공급자 로고, 계약 승인 표시와 실행 로그를 넣지 않습니다.
- 설명용 삽화를 실제 실행 증거나 설계 완료 상태로 해석하지 않습니다.
- 사용한 최종 생성 조건은 [GENERATED-IMAGE-PROMPTS.md](GENERATED-IMAGE-PROMPTS.md)에 기록합니다.

## 결과 요약 이미지 원칙

- `02`~`05`, `09`도 설명용 삽화와 같은 노트 종이·네이비 펜·제한된 파랑/초록/노랑 스타일을 사용합니다.
- 종이 질감만 ImageGen으로 만들고, 한글·수치·표·막대는 `source/result-sheets.html`에서 정확하게 렌더링합니다. 이미지 모델이 숫자나 글자를 다시 쓰게 하지 않습니다.
- 공통 배경은 `source/result-paper-background.png`이며 결과표 다섯 장은 Velog 모바일에서도 숫자를 읽기 쉽도록 1080×1350px 4:5 세로형으로 렌더링합니다.
- 결과표를 다시 만들 때는 Chrome, Pretendard, D2Coding과 `playwright-core`가 필요합니다. 저장소 루트에서 `node scripts/render-blog-result-sheets.cjs`를 실행하며, 자동 탐색이 안 되면 `PLAYWRIGHT_CORE_PATH`와 `CHROME_BIN`을 지정합니다.
- 결과표는 실제 실행 로그 원본이 아니라 읽기 쉽게 옮긴 요약입니다. 값이 바뀌면 원본 보고서와 대조한 뒤 본문·표·캡션도 함께 고칩니다.

## 흐름도 이미지 원칙

- Velog가 Mermaid 코드 블록을 렌더링하지 않아 본문 흐름도는 PNG로 제공합니다.
- `10`~`13`은 생성형 이미지가 아니라 `source/blog-diagrams.html`의 고정 문구와 SVG 연결선을 Chrome으로 렌더링한 1080×1350px 세로형 이미지입니다.
- 실선·점선·성공·실패의 의미는 색상만으로 구분하지 않고 이미지 안의 문구와 본문 캡션으로 함께 설명합니다.
- 다시 만들 때는 `PLAYWRIGHT_CORE_PATH`와 필요하면 `CHROME_BIN`을 지정해 `node scripts/render-blog-diagrams.cjs`를 실행합니다.
- 렌더러는 1080×1350px 크기, 30px 최소 글자, 7% 안전 여백, overflow와 390px 폭 환산 시 10px 미만 글자 여부를 확인합니다. 출력 뒤에는 연결 방향과 문구를 원래 흐름과 다시 대조합니다.

## 캡션에 유지할 조건

- 데이터 출처는 `blog-local-seed`이며 실제 증권사 시세가 아닙니다.
- 캡처와 보고서의 commit 표시는 해당 결과를 만든 로컬 HEAD입니다. 최종 문서 commit과 다를 수 있으므로 생성 시각과 함께 확인합니다.
- Flutter 캡처 빌드에만 역사 시드를 조회하기 위한 `MARKET_CANDLE_LOOKBACK_DAYS=7`을 사용했습니다. 일반 빌드는 가장 최근 거래일을 자동 계산합니다.
- 차트는 조회 데이터 중 최신 48개를 그립니다.
- API 마지막 값은 `2026-08-07 15:29 KST`, O 76,200 / H 76,700 / L 75,900 / C 76,300 / V 6,945 / 체결 39 / final true / revision 1입니다.
- `MarketService` 상세 가격과 `blog-local-seed` 마지막 분봉 종가는 다섯 종목 모두 의도적으로 일치합니다. 서로 다른 로컬 데이터셋의 표시 계약이며 실시간 동기화 증거가 아닙니다.
- 새 시드는 종목별 장중 연결과 1분 간격이 각각 1,945/1,945쌍이었습니다. 잘못된 OHLCV와 동적 가격 단위 위반은 0건, 최대 움직임은 2틱, 종목별 각 거래일의 움직임 합계는 0입니다.
- 가격 단위는 삼성전자·SK하이닉스·NAVER 100원, 카카오 50원, 현대차 500원입니다. 거래일 갭은 -2틱에서 +2틱이며 전체 금액 범위는 -1,000원에서 +1,000원이지만 종목마다 다릅니다.
- 기존 삼성전자 하루 시드는 인접한 389쌍 중 연결된 쌍이 0개였고, 다음 시가와 이전 종가의 평균 차이는 187.61원, 최댓값은 740원이었습니다.
- 장중 연속성은 로컬 교육용 규칙입니다. 실제 시장에서는 시초가, 거래 중단, 체결 공백으로 가격 갭이 생길 수 있으며 실제 공급자 값을 임의로 고치지 않습니다.
- 캔들 모드는 봉끼리 선을 긋지 않습니다. 인접 가격과 시간 위치로 이어져 보이며, 라인 모드만 연속 구간의 종가를 선으로 잇습니다. 누락된 1분은 공백 또는 끊어진 선으로 표시합니다.
- gzip은 1일 `56,658B → 5,177B`, 5일 `282,858B → 24,230B`로 각각 90.9%, 91.4% 줄었습니다.
- B0의 5일·100 VU는 세 번 모두 p95 200ms 기준을 통과했지만 최악 p95는 196.651ms였습니다. 이 근접 결과가 B1 재검증의 출발점입니다.
- B1에서는 모든 조건을 세 번씩 실행했고 5일·100 VU p95가 203.918ms, 202.757ms, 210.552ms로 세 번 모두 실패했습니다. 모든 실행의 HTTP 오류율은 0%, 상태·`success`·최소 봉 수 검사는 100%였습니다.
- B0와 B1의 환경이 완전히 같다고 입증할 수 없으므로 성능 회귀로 단정하지 않습니다. B1은 한 Mac에서 관찰한 포화 신호이며 병목 원인은 미측정입니다.
- API 토큰, Authorization 헤더, 계정 정보와 로컬 사용자 경로는 이미지에 넣지 않습니다.

## 재현할 때

1. `scripts/blog-market-candles-seed.sh catalog-week`로 같은 5종목·5거래일 데이터를 만듭니다.
2. 서버를 실행하고 `scripts/blog-market-candles-evidence.sh`로 예상 5종목·종목별 1,950개·첫/마지막 시각 경계를 확인합니다.
3. 삼성전자 DB와 API의 1,950개 분봉에서 시간·OHLCV·체결 수·확정 여부·revision을 순서대로 전부 비교합니다.
4. 종목별 연결·1분 간격 1,945/1,945쌍, 잘못된 OHLCV·가격 단위 위반 0건, 최대 2틱과 일별 이동 합계 0을 확인합니다.
5. 한 ticker 전체와 첫·마지막·중간 봉 삭제, `high + 1` 훼손이 각각 실패하고 재적재 뒤 복구되는지 확인합니다.
6. `benchmarkMinuteCandleStorage`와 `benchmarkMinuteCandles`를 각각 실행합니다.
7. 1일·5일을 10·100 VU로 나누어 k6를 조건별 20초씩 세 번 실행합니다. 두 번째 반복은 높은 부하부터 역순으로 실행하고 실행별 고유 ID를 사용합니다.
8. 서버 `unitTest` 73개와 `integrationTest` 27개, Flutter 테스트 62개와 정적 분석 결과를 확인합니다.
9. 실행 manifest, 환경, 원시 요약 hash를 함께 보존하고 새 결과가 본문과 다르면 이미지뿐 아니라 표, 캡션, 해설도 함께 갱신합니다.

## 화면과 API의 값 대조

차트 화면이 보이는 것만으로 API 연동을 검증했다고 판단하지 않습니다.

1. 네트워크 응답에서 마지막 분봉의 `time`과 OHLCV를 기록합니다.
2. Flutter 차트의 마지막 캔들과 상세 현재가가 같은 시간과 종가를 사용하는지 확인합니다.
3. 클라이언트가 종가 목록으로 OHLC를 임의 생성하지 않는지 확인합니다.
4. 인접 봉의 시간 차이가 실제 분 차이와 같은지, 누락된 분을 붙여 그리지 않는지 확인합니다.
5. 화면 캡션에 사용한 ticker와 조회 범위를 적습니다.

## 본문에 캡처를 넣을 때

각 캡션에는 로컬에서 직접 확인한 결과와 그 결과가 보장하지 않는 범위를 함께 적습니다. before 화면은 잘못된 독립 시가 생성의 문제를, after 화면은 최신 48개와 시간축 표현을 보여줍니다. API 이미지는 DB·응답·연속성 검사의 일치를, 성능 이미지는 같은 Mac에서 실행한 짧은 비교 시험임을 밝힙니다. 실제 공급자 품질, 운영 사용자 수, 장시간 안정성은 이 이미지들로 증명하지 않습니다.

## Velog에 옮길 때

1. 저장소의 `assets/...` 상대 경로는 원본 문서용으로 유지합니다.
2. Velog 편집기에는 각 PNG를 직접 올리고, 에디터가 만든 이미지 주소로 게시용 본문의 경로를 바꿉니다.
3. `thumbnail-minute-candles-final.png`를 대표 이미지로 선택합니다.
4. 업로드 뒤에도 본문에 적은 대체 문구와 캡션을 함께 옮깁니다.
5. 설명용 삽화는 실제 증거처럼 소개하지 않고, 화면과 측정 결과 요약은 각각의 한계를 유지합니다.
6. `10`~`13` 흐름도 PNG도 직접 올리고 본문의 경로를 에디터가 만든 이미지 주소로 바꿉니다. Mermaid 코드 블록을 별도로 옮기지 않습니다.
