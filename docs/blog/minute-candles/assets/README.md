## 캡션에 유지할 조건

- 데이터 출처는 `blog-local-seed`이며 실제 증권사 시세가 아닙니다.
- 캡처와 보고서의 commit 표시는 해당 결과를 만든 로컬 HEAD입니다. 최종 문서 commit과 다를 수 있으므로 생성 시각과 함께 확인합니다.
- Flutter 캡처 빌드에만 역사 시드를 조회하기 위한 `MARKET_CANDLE_LOOKBACK_DAYS=7`을 사용했습니다. 일반 빌드는 가장 최근 거래일을 자동 계산합니다.
- 차트는 조회 데이터 중 최신 48개를 그립니다.
- API 마지막 값은 `2026-08-07 15:29 KST`, O 76,200 / H 76,700 / L 75,900 / C 76,300 / V 6,945 / 체결 39 / final true / revision 1입니다.
- 상세 현재가와 마지막 분봉 종가는 다섯 종목 모두 일치합니다.
- 새 시드는 종목별 장중 연결과 1분 간격이 각각 1,945/1,945쌍이었습니다. 잘못된 OHLCV와 동적 가격 단위 위반은 0건, 최대 움직임은 2틱, 종목별 각 거래일의 움직임 합계는 0입니다.
- 가격 단위는 삼성전자·SK하이닉스·NAVER 100원, 카카오 50원, 현대차 500원입니다. 거래일 갭은 -2틱에서 +2틱이며 전체 금액 범위는 -1,000원에서 +1,000원이지만 종목마다 다릅니다.
- 기존 삼성전자 하루 시드는 인접한 389쌍 중 연결된 쌍이 0개였고, 다음 시가와 이전 종가의 평균 차이는 187.61원, 최댓값은 740원이었습니다.
- 장중 연속성은 로컬 교육용 규칙입니다. 실제 시장에서는 시초가, 거래 중단, 체결 공백으로 가격 갭이 생길 수 있으며 실제 공급자 값을 임의로 고치지 않습니다.
- 캔들 모드는 봉끼리 선을 긋지 않습니다. 인접 가격과 시간 위치로 이어져 보이며, 라인 모드만 연속 구간의 종가를 선으로 잇습니다. 누락된 1분은 공백 또는 끊어진 선으로 표시합니다.
- gzip은 1일 `56,658B → 5,177B`, 5일 `282,858B → 24,230B`로 각각 90.9%, 91.4% 줄었습니다.
- 5일·100 VU는 세 번 모두 p95 200ms 기준을 통과했지만, 최악의 실행은 p95 196.651ms와 p99 337.026ms였습니다. 로컬 20초 결과를 운영 보장으로 해석하지 않습니다.
- API 토큰, Authorization 헤더, 계정 정보와 로컬 사용자 경로는 이미지에 넣지 않습니다.

## 재현할 때

1. `scripts/blog-market-candles-seed.sh catalog-week`로 같은 5종목·5거래일 데이터를 만듭니다.
2. 서버를 실행하고 `scripts/blog-market-candles-evidence.sh`로 예상 5종목·종목별 1,950개·첫/마지막 시각 경계를 확인합니다.
3. 삼성전자 DB와 API의 1,950개 분봉에서 시간·OHLCV·체결 수·확정 여부·revision을 순서대로 전부 비교합니다.
4. 종목별 연결·1분 간격 1,945/1,945쌍, 잘못된 OHLCV·가격 단위 위반 0건, 최대 2틱과 일별 이동 합계 0을 확인합니다.
5. 한 ticker 전체와 첫·마지막·중간 봉 삭제, `high + 1` 훼손이 각각 실패하고 재적재 뒤 복구되는지 확인합니다.
6. `MinuteCandleStorageMetricsIT`와 `benchmarkMinuteCandles`를 각각 실행합니다.
7. 1일·5일을 10·100 VU로 나누어 k6를 20초 실행합니다. 5일·100 VU는 세 번 독립 실행합니다.
8. 서버 `*Test` 55개와 `*IT` 24개, Flutter 테스트 62개와 정적 분석 결과를 확인합니다.
9. 새 결과가 본문과 다르면 이미지뿐 아니라 표, 캡션, 해설도 함께 갱신합니다.

## 화면과 API의 값 대조

차트 화면이 보이는 것만으로 API 연동을 검증했다고 판단하지 않습니다.

1. 네트워크 응답에서 마지막 분봉의 `time`과 OHLCV를 기록합니다.
2. Flutter 차트의 마지막 캔들과 상세 현재가가 같은 시간과 종가를 사용하는지 확인합니다.
3. 클라이언트가 종가 목록으로 OHLC를 임의 생성하지 않는지 확인합니다.
4. 인접 봉의 시간 차이가 실제 분 차이와 같은지, 누락된 분을 붙여 그리지 않는지 확인합니다.
5. 화면 캡션에 사용한 ticker와 조회 범위를 적습니다.

## 본문에 캡처를 넣을 때

각 캡션에는 로컬에서 직접 확인한 결과와 그 결과가 보장하지 않는 범위를 함께 적습니다. before 화면은 잘못된 독립 시가 생성의 문제를, after 화면은 최신 48개와 시간축 표현을 보여줍니다. API 이미지는 DB·응답·연속성 검사의 일치를, 성능 이미지는 같은 Mac에서 실행한 짧은 비교 시험임을 밝힙니다. 실제 공급자 품질, 운영 사용자 수, 장시간 안정성은 이 이미지들로 증명하지 않습니다.
