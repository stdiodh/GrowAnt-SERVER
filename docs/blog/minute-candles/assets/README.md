## 캡션에 유지할 조건

- 데이터 출처는 `blog-local-seed`이며 실제 증권사 시세가 아닙니다.
- 서버 기준 commit은 `b377c21`입니다. Flutter 캡처는 client `348c1a0` 기반 작업 트리에서 생성했습니다.
- Flutter 캡처 빌드에만 역사 시드를 조회하기 위한 `MARKET_CANDLE_LOOKBACK_DAYS=7`을 사용했습니다. 일반 빌드는 가장 최근 거래일을 자동 계산합니다.
- 차트는 조회 데이터 중 최신 60개를 그립니다.
- API 마지막 값은 `2026-08-07 15:29 KST`, O 76,730 / H 76,810 / L 76,700 / C 76,770 / V 4,733 / 체결 27 / final true / revision 1입니다.
- API 토큰, Authorization 헤더, 계정 정보와 로컬 사용자 경로는 이미지에 넣지 않습니다.
- k6의 5일·100 VU는 p95 200ms 기준을 세 번 모두 넘겼다는 사실을 캡션에서 숨기지 않습니다.

## 재현할 때

1. `scripts/blog-market-candles-seed.sh catalog-week`로 같은 5종목·5거래일 데이터를 만듭니다.
2. 서버를 실행하고 `scripts/blog-market-candles-evidence.sh`로 DB와 API의 개수·마지막 값을 대조합니다.
3. `MinuteCandleStorageMetricsIT`와 `benchmarkMinuteCandles`를 각각 실행합니다.
4. 1일·5일을 10·100 VU로 나누어 k6를 실행합니다. 5일·100 VU는 세 번 반복합니다.
5. `./gradlew test --tests '*IT'` 결과에서 전체 테스트 수와 실패·건너뜀을 확인합니다.
6. 새 결과가 본문과 다르면 이미지뿐 아니라 표, 캡션, 해설도 함께 갱신합니다.

## 화면과 API의 값 대조

차트 화면이 보이는 것만으로 API 연동을 검증했다고 판단하지 않습니다.

1. 네트워크 응답에서 마지막 분봉의 `time`과 `close`를 기록합니다.
2. Flutter 차트의 마지막 캔들이 같은 시간과 종가를 사용하는지 확인합니다.
3. 클라이언트가 종가 목록으로 OHLC를 임의 생성하지 않는지 확인합니다.
4. 화면 캡션에 사용한 ticker와 조회 범위를 적습니다.

## 본문에 캡처를 넣을 때

각 캡션에는 로컬에서 직접 확인한 결과와 그 결과가 보장하지 않는 범위를 함께 적습니다. Flutter 화면은 로컬 시드와 최신 60개 렌더링을, API 이미지는 DB와 응답의 일치를, 성능 이미지는 같은 Mac에서 실행한 짧은 비교 시험임을 밝힙니다. 실제 공급자 품질, 운영 사용자 수, 장시간 안정성은 이 이미지들로 증명하지 않습니다.
