FLOW 01 · EVENT TIME

세 체결이 1분봉이 되는 과정

발생 시각 순서로 OHLC를 정하고 수량을 더해 거래량을 만듭니다.

체결 1 · 09:00:0570,000원10주
체결 2 · 09:00:2070,500원5주
체결 3 · 09:00:5069,800원8주
분 버킷09:00 1분봉발생 시각 기준 집계
O · 시가70,000
H · 고가70,500
L · 저가69,800
C · 종가69,800
V · 거래량23주

거래량은 10 + 5 + 8 = 23주입니다. 같은 값이어도 저가와 종가는 서로 다른 항목입니다.

FLOW 03 · WATERMARK

분 종료 뒤 5초를 더 기다리는 이유

늦게 도착한 체결을 받을 시간을 둔 뒤 1초 간격 스케줄러가 확정합니다.

09:00:00수집 시작
09:01:001분 종료
09:01:05 이후최초 확정 가능
개념도 · 간격 비례 아님 늦은 체결 허용 · 5초
실제 확정은 보통 종료 후 약 5~6초 1초 간격 스케줄러 실행 시점에 따라 달라집니다.

5초는 운영 SLA나 정답이 아니라 POC 초기값입니다. 실제 공급자의 지연 분포를 측정한 뒤 조정합니다.

FLOW 04 · RETRY

DB 저장 실패에도 확정 봉은 남깁니다

성공한 봉만 pending에서 제거하고 실패한 봉은 다음 주기에 재시도합니다.

분봉 확정
저장 대기 pending프로세스 메모리
DB 저장 결과?
성공pending에서 제거
실패pending에 유지
성공 실패 다음 주기에 다시 시도

pending은 내구성 큐가 아닙니다. 서버 종료 시 저장 대기 봉이 보존되지 않아 REST 복구가 필요합니다.
